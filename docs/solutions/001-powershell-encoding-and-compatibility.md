# 001. Кодировка UTF-8 BOM, совместимость PowerShell 5.1 и безопасный вызов утилит

**Статус:** Принято / Реализовано  
**Дата:** 2026-08-20 (Обновлено: 2026-09-09)  
**Компоненты:** `Toolbox.bat`, `Toolbox.ps1`  

---

## 1. Контекст и симптомы проблемы

При создании универсального скрипта для сисадминских флешек на базе PowerShell и CMD возникли три критические платформенные проблемы:

1. **Сбой парсера Windows PowerShell 5.1 на кириллице:**
   * *Симптом:* При запуске `.ps1` файла с русским текстом консоль выдавала каскад ошибок `Unexpected token ')'`, `Missing closing '}'`, `Unexpected token '['`.
   * *Первопричина:* Windows PowerShell 5.1 (штатный в Windows 10/11) по умолчанию читает файлы без BOM в системной локали ANSI (Windows-1251 / CP866). Двухбайтовые последовательности UTF-8 для русских букв разбиваются на байты, совпадающие с ASCII-кодами кавычек `"` и скобок `]`, что ломает синтаксис на этапе парсинга AST.
2. **Падение на тернарном операторе `?:`:**
   * *Симптом:* `Unexpected token '?' in expression or statement`.
   * *Первопричина:* Тернарный оператор `?:` появился только в PowerShell Core 7+. Стандартный `powershell.exe` (версии 5.1 и ниже) падает с фатальной синтаксической ошибкой.
3. **Блокировка HTTPS (TLS 1.2/1.3) на Windows 7 / 8.1:**
   * *Симптом:* Команды загрузки с GitHub (`irm https://...`) выдавали ошибку защищенного канала SSL/TLS.
   * *Первопричина:* По умолчанию в .NET Framework 3.5/4.5 на Windows 7 отключены современные протоколы безопасности.

---

## 2. Реализованное решение

1. **Обязательное сохранение в `utf-8-sig` (UTF-8 с BOM):**
   * Все `.ps1` файлы проекта должны сохраняться строго в кодировке `UTF-8 с меткой порядка байтов (BOM)`. Это заставляет интерпретатор PS 5.1 включить корректный UTF-8 парсер строк.
2. **Исключение синтаксиса PowerShell 7+:**
   * Замена всех тернарных операторов на нативные конструкции PowerShell 5.1:
     ```powershell
     $arch = if ([Environment]::Is64BitOperatingSystem) { "x64" } else { "x86" }
     ```
3. **Динамический UAC-лаунчер (`Toolbox.bat`):**
   * Разделение проекта на чистый `.bat` лаунчер (авто-элевация прав администратора через `Start-Process -Verb RunAs`) и внешний изолированный `.ps1` скрипт, что исключает ошибки передачи кода через командную строку CMD.
4. **Принудительная активация TLS 1.2/1.3 в первой строке сессии:**
   ```powershell
   [Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12 -bor [Net.SecurityProtocolType]::Tls13
   ```
5. **Централизованный диспетчер `Invoke-Tool`:**
   * Единая точка запуска приложений с проверкой путей, фоллбэком на официальные сервера при отсутствии локального файла и отсутствием пустых `catch {}` блоков.
